# المرحلة 19 — مراجعة الربط والتزامن

فحصنا استدعاءات الشركاء والإدارة: أسماء RPC ومعاملاتها متطابقة مع SQL المرفق.

**المشكلة المؤكدة:** قفل الصفوف الموجودة FOR UPDATE لا يمنع إضافة صف تغطية جديد أثناء تأكيد نقل الزون.

**التصحيح:** كلا مساري حفظ التغطية (الشركاء v2) وتأكيد النقل (الإدارة v2) يأخذان نفس قفل المعاملة advisory transaction lock لكل متجر، قبل تعديل البيانات. ثم يفحص تأكيد النقل بصمة التغطية بعد القفل.

**حدود الحماية:** أي مسار كتابة آخر للتغطية (بما فيه دالة v1 القديمة أو تعديل مباشر عبر SQL) لا يأخذ القفل سيبقى خارج ضمان التزامن؛ يجب ترحيل/تعطيل جميع مسارات الكتابة الأخرى قبل النشر. التغيير لا يحل مشكلة أجور الطلبات المؤجلة.

**الترتيب:** تنفيذ SQL إنشاء الجداول والمراحل الأساسية أولاً، ثم SQL المرحلة 19 للإدارة والشركاء في معاملة نشر منسقة، ثم اختبار على بيئة تجريبية. لا تنفذ أو تنشر حالياً.

فحص ملفات ZIP وJavaScript فقط، دون بناء Flutter أو اختبار Supabase.
