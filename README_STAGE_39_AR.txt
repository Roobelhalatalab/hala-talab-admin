هلا طلب — لوحة الإدارة Stage 39

مبنية مباشرة على Stage 38 المعتمدة.

التعديلات المحصورة في هذه المرحلة:
1) إدارة كوبونات المتاجر من لوحة الإدارة مع بقاء المصدر «متجر» واضحًا.
2) زر إيقاف/تفعيل وحذف إداري آمن لكوبونات المتاجر عبر RPC بدل الاعتماد على RLS المباشر.
3) إدارة عروض المتاجر بنفس الطريقة مع منع أي خلط مع عروض الإدارة source=admin.
4) إظهار قاعدة الاستخدام في الجداول: الكوبون مرة واحدة لكل عميل، والعرض متكرر حتى الانتهاء ما لم يوجد حد لكل عميل.
5) ضغط/تصغير صور تصنيفات العميل قبل رفعها إلى Supabase: حد أقصى 640px وتحويل WebP عند ما يكون أخف، مع الحفاظ على الصورة الأصلية إذا كانت أصغر.
6) رفع Cache-Control لصور التصنيفات إلى سنة لتقليل إعادة التحميل.
7) تحديث PWA cache إلى Stage 39 فقط، بدون لمس OneSignal أو Push.

SQL المطلوب مرة واحدة:
_setup/STAGE_39_ADMIN_STORE_COUPON_OFFER_MANAGEMENT.sql

ملاحظة: هذا SQL لا يغيّر منطق الاستهلاك الموجود في العميل؛ يضيف فقط صلاحيات إدارة آمنة للوحة الإدارة.

إضافة ضمن نفس Stage 39 قبل التجميع النهائي:
- زر حذف نهائي للمتجر: يحذف سجل المتجر فعليًا بدل منعه بسبب وجود طلبات تاريخية، ويختفي من قوائم العميل والإدارة.
- زر حذف نهائي للسائق: يحذف حساب السائق من auth.users؛ علاقات driver_id من نوع SET NULL تحفظ الطلبات التاريخية بدون ربط بالسائق.
- زر حذف نهائي للمستخدم/العميل: متاح للحساب العادي مع منع حذف حساب الإدارة الحالي، ومنع حذف صاحب متجر أو سائق من القسم الخطأ.
- جميع عمليات الحذف تتطلب تأكيدًا كتابيًا ثم تأكيدًا نهائيًا.
- لا تشغّل SQL الآن إذا ما زالت ملاحظات الإدارة مستمرة؛ سيتم جمعه في آخر ملف SQL نهائي حسب الاتفاق.


تصحيح إضافي Stage 39:
- إصلاح الحذف النهائي للمتجر: حذف ربط السائقين من driver_delivery_scope بدل تصفير store_id، لمنع خطأ driver_delivery_scope_store_required.
- بعد هذا التصحيح يجب إعادة تشغيل ملف SQL الخاص بـ Stage 39 مرة واحدة (CREATE OR REPLACE آمن للتحديث).
